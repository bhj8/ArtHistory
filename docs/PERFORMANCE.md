# 首页加载优化

2026-09-22。数据规模保持 233 条目、660 幅图片；作品原图不变。

## 加载方式

- 构建生成 `data/catalog.json`，仅包含浏览、筛选、图库所需的目录数据。首页只请求这一份数据。
- `data/search-index.json` 在构建时预先生成。第一次搜索才下载并恢复索引，浏览器不再计算作者关联和完整检索文本。
- `data/details/<id>.json` 在打开相应条目时加载，含正文、关联、配图完整资料和引用来源。
- 从图库直接选作品对照时，用 `data/works/<id>.json` 补充作品资料。已随条目加载的作品直接复用。
- 完整资料来源列表在打开“资料来源”时请求。失败的请求可重试，并发请求复用同一个 Promise。
- HTML 提前声明目录数据及模块预加载，减少脚本逐层发现、再请求数据的等待。
- 预览使用 320 / 640 像素两个尺寸，按显示大小选择。详情主图和放大视图仍加载原图。

## 可复现的对比

以默认核心地图的 36 张不同预览图片计算，图片从 3,361,688 字节降为 467,750 字节（320 像素版本，约减少 86%）。高像素密度屏幕可能选择部分 640 像素版本。

原来首页需要 12 份 JSON，线上 gzip 实测合计 213,378 字节；新目录 gzip 约 91 KB，其余资料按需请求。原首页模块、样式、HTML、数据及上述图片合计约 3.61 MB；新版本约 0.60 MB。这里是资源体积对比，不是首屏时间测量，也不包含 Cloudflare 额外注入的统计脚本和 HTTP 头。

同一开发机上，旧目录和搜索初始化约 764—780 毫秒；新目录初始化约 15 毫秒以内。浏览器整页体验还受连接、服务器响应、解码和设备影响。

`npm run build` 包含构建产物测试：检查按需请求、并发去重、失败重试、搜索结果等价、来源完整性、原图保留及首屏资源预算。`LOG_REQUESTS=1` 启动预览服务可记录实际请求路径。

## 维护

新增或修改位图后，使用已安装 Pillow 的 Python 运行 `scripts/thumbnails.py`。将 `assets/thumbnails/` 和 `data/thumbnails.json` 一起提交。校验会核对原图摘要，发现缩略图未更新时拒绝构建。

正常发布只需 Node.js，不需要 Python 或新增 npm 依赖。`npm run dev` 会先生成发布目录再启动预览；修改源文件后重新构建、刷新预览。`dist/` 始终为忽略的生成文件，不提交。
