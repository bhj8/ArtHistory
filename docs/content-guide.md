# 内容维护说明

## 新增知识条目

在 `data/entries/` 中选择分类文件：`west`、`china`、`asia`、`world`、`design` 或 `media`。复制相邻条目，填写以下字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一且稳定的小写英文 ID，可带数字和连字符；用于关系、收藏和链接 |
| `lane` | 分类 ID，必须与文件名相同 |
| `era` | 时代索引，范围以 `data/taxonomy.json` 为准；0 为史前古代，6 为全球数字 |
| `zh` / `en` | 中文名称与英文名称 |
| `date` | 人可读的概略活动时段，不代表时间轴的精确比例 |
| `kind` | 历史运动、地域传统、学校、媒介、方法或标签等类别 |
| `hook` | 一句话入口 |
| `look` | 可观察的视觉特征 |
| `idea` | 核心问题与历史语境 |
| `people` | 代表人物或对象 |
| `work` | 推荐的作品和具体观察点 |
| `distinguish` | 容易混淆的概念与辨别方法 |
| `tags` | 用空格分隔的搜索关键词字符串 |
| `source` | `data/sources.json` 中的来源 ID；没有核实的来源就填空字符串 |

不要随意改变已发布的 `id`，否则旧收藏、深链接及关联会失效。时代分段是导航，而不是进化排序。新增分区时同时更新 taxonomy 和对应 entries 文件，加载器会自动发现。

## 新增作品图

1. 将压缩后的 WebP 放入 `assets/artworks/`，使用小写英文文件名。通常长边 1000～1600 像素足够；单张不得超过 2 MB。
2. 在 `data/artworks.json` 添加记录，键为关联的条目 ID。
3. 填写 `image`（例如 `assets/artworks/new-entry.webp`）、`zh`、原始 `title`、`artist`、可选 `artistZh`、`date`、`url`、`credit` 及真实的权利资料。不要把未知权利标成公共领域。
4. 确认图片展示的是对应作品，而非馆方通用封面、建筑照片或错误裁切。

当前每个条目支持一幅精选作品。这是有意明确的界面约定；将来增加多图画廊时，将 artwork 记录改为多图集合并同步更新加载器、详情与校验，不要向 HTML 继续嵌入 Base64。

## 新增关系与路线

`relationships.json` 中每行是 `[起点ID, 终点ID, 关系类型, 关系解释]`。界面双向提供导航；关系说明需要明确真正的影响方向，不能把“可比较”伪装成历史因果。不重复添加反向边。

`routes.json` 的 `ids` 数组就是建议阅读顺序。路线代表学习顺序，不代表单向历史继承。所有引用的 ID 都必须存在。

`data/sources.json` 保存核实过的资料，包含中文标题 `zh`、原标题 `title`、链接 `url`、机构 `org`。网页/图片搜索入口与已核验资料明确分开。

## 提交前

运行 `npm run check`，再用 `npm run dev` 查看新增内容。检查图片、中文名称、图注与关联。构建会只复制 `index.html`、`src/`、`data/`、`assets/` 到 `dist/`，不会把文档与开发脚本发布出去。

结构已将媒体与文本分离，图片由浏览器缓存及懒加载，类别数据便于分工维护。未来到上千条时，可以在不改条目 ID 的前提下增加检索索引和数据分页；当前不为尚未出现的规模引入数据库或重型框架。
